Program Builder — Implementation Approaches

Three ways to build this. Pick the one that feels right.

A

Minimal viable builder

Single-page form at /dashboard/admin/programs/new. Program info + a dynamic track list on one scrollable page. No step indicators, no nav — fill it out, hit Create. Fast to build, zero ceremony. Trades polish for speed of implementation.

~1–2 days to build No DB migrations needed yet Good for internal tools
B

Stepped hub + spoke wizard Recommended

Step 1: program info (name → slug auto-derived, description). Step 2: tracks hub — add/edit/remove tracks inline before committing. Step 3: review summary → Create. Clean step indicator, back/next nav. After creation: redirects to the new program's admin with a join-link banner.

~3–4 days to build DB schema for programs + tracks Lean fields now, upgradeable to full
C

Full CMS-style editor

Wizard creates the program shell, then a rich per-track editor lets you configure weeks, sessions, prompts, and content inline — like a lightweight CMS. Programs list at /dashboard/admin/programs becomes a command center. Most powerful, closest to "Option C" from earlier.

~1–2 weeks to build Full DB schema overhaul Risk: scope creep
My recommendation: B. It's the right balance — structured enough to feel intentional, lean enough to ship fast. A is fine for a prototype but feels rough for something you'll use repeatedly. C is the endgame but too much to bite off now.
